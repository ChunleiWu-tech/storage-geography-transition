# V17 验证摘要

V17 的发布语义与验证边界已经固定：

- **正式结果来源**：第一阶段求解器认证的经济最优、模型约束可行解；
- **第二阶段角色**：仅作为显式触发的稀疏最优面诊断，尝试在高度退化的最优面中选择较稀疏的运行表示；
- **非阻断原则**：第二阶段不收敛、未运行或诊断失败，均不得否决、覆盖或替换已认证的第一阶段正式结果；
- **解释边界**：投资、容量、系统成本、政策约束结果及聚合平衡可作为正式证据；毛调度、方向性输电、备用转移及储能充放电分量统一标记为退化敏感，只能用于核算重构与聚合平衡检查，不得用于运行机理解释。

## V17 专项修正

- 第一阶段默认配置为 `stage1_official_release`，正式输出源固定为 `stage1_solver_certified_economic_optimum`。
- 正式 `__main` 路径只允许第一阶段结果；controlled 后备仅在第一阶段未取得认证时，使用新的 Julia 进程切换第一阶段算法，不调用第二阶段清理路线。
- 显式诊断启动器改为 `RUN_V17_SL00_SPARSE_FACE_DIAGNOSTIC_1x10.bat`；其成功输出也永久标记为 `diagnostic_sparse_face_result_not_for_publication`，不会被后处理正式门槛接纳。
- 新增 `RESULT_INTERPRETATION_POLICY.csv`；`dispatch.csv`、`DispatchTx.csv` 和 `storage_operation_audit.csv` 均携带结果来源、退化敏感性、机理解释许可和允许用途字段。
- 同时充放电、方向性输电对流和备用对流检查改为非阻断披露；正式投资与经济规划结果仍须通过全部硬物理闭合、碳核算、规划备用和导出审计。
- `GRB_ERROR_DATA_NOT_AVAILABLE = 10005` 保持在生产主程序模块顶层；函数作用域内不存在 Julia 不支持的局部 `const`。
- JSON 非有限值安全转换为 `null`；不读取或持久化 `VBasis`、`CBasis`、`CrossoverBasis`、`DStart` 或 PStart。

## 本环境未执行的项目

本构建环境没有 Julia/Gurobi 运行时及许可证，因此未执行生产主程序真实 include、Gurobi 探针或百万级 SL00 数值求解。已完成的是代码、配置、输入、审计链、场景重建和后处理输入级验证；正式本地数值认证仍应依次运行：

```powershell
.\CHECK_V17_RELEASE.bat
.\CHECK_V17_SOURCE_LOAD.bat
.\CHECK_V17_RUNTIME.bat
.\RUN_V17_SL00_PRIMARY_ONLY_1x10.bat
```
